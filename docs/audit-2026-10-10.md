# 2026-10-10 自查与修订

本轮重点核对检查/清理/回收的执行路径、跨页异步状态、扫描边界、体检数据与依赖。沿用现有 WinEase 界面和确认流程，优先修可靠性问题，没有增加新的技术选择项。

## 已修复

| 问题 | 调整 |
| --- | --- |
| 离开清理页会卸载组件，扫描和勾选丢失 | 清理页保持挂载，扫描在首次进入时启动；扫描过程中去其他页面、返回查看或手动取消勾选均保留状态。打开首页不会顺带触发隐藏清理扫描。 |
| 清理遍历没有统一上限 | 所有缓存根目录共用 120 秒/500,000 个条目的检查预算，保留已检查项目，清理页与首页明确显示部分结果。上限为遍历过程的合作式检查，不保证单个 Windows 文件系统调用能立即返回。 |
| 重复文件回收前在异步执行器和扫描结果锁内重复读取哈希 | 在后台线程校验，只短暂锁定/克隆扫描证据，同一组保留文件只校验一次；一次计划共用 180 秒哈希预算。其他扫描可以在校验期间发布结果，失败校验不消耗原令牌。移动前仍核实所选文件和保留文件的元数据；至少保留一份。 |
| 清理或回收请求被拒绝后仍清空页面 | 拒绝请求时保留检查列表和错误，便于重新选择或扫描。真正执行后令牌消费，页面按实际结果结束该次计划。 |
| 缺失容量被当作 0，配置读取失败可能被标记正常 | PowerShell 保留缺失值，Rust 校验有效容量及内存范围；缺失/异常数据标未核实，错误优先于表面布尔值。Defender 数据不完整时不生成虚假未开启提示；防火墙未明确开启/关闭时不标正常。 |
| 检查脚本固定端口与默认开发端口不一致 | 页面回归脚本统一使用 Vite 默认 1420，补充可复现的失败与跨页用例。 |

## 后续仍需关注

1. **大盘覆盖率与速度**：当前全盘统计与重复扫描有时间/数量上限，结果可能不完整。今后的主要增量应是更快的文件索引和渐进结果，而不是继续增加清理类别或默认删更多文件。
2. **可观察的执行进度**：首页已有项目执行进度；一个缓存批次含大量文件时，逐文件进度仍可进一步完善。不能用定时器制造清理百分比。
3. **发布验收**：原生 UAC 网络修复、全部第三方组件安装/卸载、旧客户端签名更新仍需隔离设备验收。保持现有草稿 PR，不把浏览器夹具当作这些操作的实机证据。
