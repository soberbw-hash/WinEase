## 适合 WinEase 的功能

| 优先级 | 能力 | 产品行为与实施边界 |
| --- | --- | --- |
| 本轮 | 减少推广、推荐应用自动安装 | 两个独立开关。首次写入先备份，写入后读回验证，支持恢复原值；已有应用和文件同步保留。Windows 版本或组织策略可能限制效果，不承诺屏蔽所有广告。 |
| 高 | 应用缓存规则扩展 | 按应用 → 缓存类型 → 文件明细组织；识别各用户配置目录，合并同名规则，保护浏览器会话、账号、聊天内容。正在使用的文件跳过并解释，逐项显示实际释放空间。已有 Chrome/Electron/开发工具规则继续完善，不能只增加类别名称。 |
| 高 | 预装应用管理 | 列出真实已安装包、用途、占用、依赖和恢复方式；默认只建议可独立移除的可选应用。保留 Store、WebView、系统外壳与安全组件；当前用户移除与系统预配移除分开。尚未实现新的 AppX 精简流程。 |
| 高 | 开机与后台影响分析 | 从“启动项很多”升级为启动影响、持续 CPU/内存占用证据；只给少量可操作建议。同步、输入法、驱动、安全软件不能仅按数量默认关闭。尚未新增持续采样。 |
| 高 | 更新和应用安装故障修复 | 区分 Windows Update、WinGet、商店故障；检查相关服务、错误记录、下载状态，先诊断再局部处理并复检。现有系统文件修复保留，不把所有故障都导向 DISM/SFC。专用更新/WinGet 修复尚未实现。 |
| 中 | 游戏与工作场景调优 | 检查后台录制、游戏模式、电源计划和更新带宽；解释影响，按设备与场景给建议。已有部分系统入口，不能等同于应用内自动优化。 |
| 中 | 本地搜索和通知偏好 | 将网页搜索、搜索热点、推荐通知分别处理；逐 Windows 版本验证，保留搜索与重要通知。当前不直接复制整个策略脚本。 |

以上优先级是产品决策，不是性能基准结论。下一轮先完成缓存覆盖与扫描完整度，再做精准预装应用管理和启动影响；避免继续增加大量仅打开系统设置的入口。

## 一键优化如何组织

首页依旧只有主要检查动作。内部规则分为：建议处理、可选偏好、需人工确认三类。每项包含检测证据、适用条件、执行、恢复、复检；界面只展示当前机器适用的建议。先完整列出，再由用户确认执行。新推广开关本轮放系统工具，尚未接入首页自动建议，不能在启动时悄悄应用。

缓存可以按规则推荐；大文件不是垃圾，重复文件至少保留一份且不能破坏应用依赖。个人文件、卸载应用、网络重置等需要明确范围。任务间分别管理状态，切页和单个组件更新不阻塞其他任务。

## 不采用为默认方案

- 关 Defender、防火墙或永久停用更新，批量禁用未知服务。
- 改 HPET/计时器、关闭页面文件、强制清空待机内存等无当前设备证据的“通用提速”。
- 注册表“垃圾”扫除、把开发缓存/游戏数据/聊天文件都当可自动删除的垃圾。
- 在线下载脚本直接执行、重做系统镜像或替用户卸载所有预装包。
- 透明任务栏、任务栏样式、主题、字体和动画美化。本轮移除 WinEase 对应入口；保留任务栏无响应修复。

## 本轮代码完成情况

- 移除透明效果开关及视觉效果、任务栏设置入口；系统管理入口由 16 项调整为 14 项。
- 新增 `SilentInstalledAppsEnabled` 和 `ShowSyncProviderNotifications` 的当前用户配置读写；开启这两个减少推广开关对应注册表值 `0`，不能按普通正向开关误读。
- 沿用首次原值备份、未知状态处理、单项错误隔离、自动资源管理器刷新与恢复机制。
- 没有运行外部优化脚本，没有更改本机用户偏好。回归采用独立测试注册表键与模拟 IPC；不能替代不同 Windows 版本的实际推广效果验收。

验证：TypeScript/Vite 构建通过，Rust 回归 74 项通过、11 项显式忽略；独立测试键覆盖四项配置的写入和恢复。本机四项配置只读查询通过；浏览器模拟 IPC 的 9 组系统流程通过，覆盖美化入口移除、新开关调用、恢复、任务独立性和窗口适配。本机运行中的软件仍是上一轮构建，本轮没有中断它或发布新安装包。
