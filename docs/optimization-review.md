# v3.5 优化审查

## WinEase 品牌

软件、窗口、npm/Cargo 项目、GitHub 仓库和安装包更名为 WinEase。界面采用与用户图标协调的蓝色强调色，保留极简布局。侧栏、关于页、favicon、应用 EXE、安装和卸载程序统一使用用户提供的工具箱图案。

原图按字节保存于 `docs/branding/icon-master.png`，安装包附带 `branding/` 原图与说明；生成脚本校验 SHA-256，使用 Tauri 官方工具生成多尺寸资源。旧配置键、数据目录和注册表备份位置继续兼容，进程保护覆盖新旧 EXE 名称。

更名后的 19 项 Rust 测试、前端生产构建和 NSIS 打包通过。真实打包程序的窗口标题、首页、关于页、图标加载及无横向溢出已检查；从 EXE 和安装程序提取的图标已人工查看，NSIS 脚本确认原图打包路径与安装/卸载图标设置。

## 技术选择

继续使用 Tauri 2 + Rust + WebView2 Evergreen。工具箱需要调用 Windows 系统接口和扫描文件，Rust 负责校验与执行，WebView2 负责界面。当前升级 Tauri 2.12.1、tauri-build 2.7.1、opener 2.7.0、React 19.3、Vite 8、TypeScript 7，并更新锁文件。安装包明确使用 WebView2 Evergreen bootstrapper。

这里的框架升级不修改 Windows 内核。未来继续扩展清理分类与 Windows 设置，通过固定后端命令实现，避免网页直接执行任意脚本。

参考：[Tauri 进程模型](https://tauri.app/concept/process-model/)、[WebView2 分发](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)、[Windows 设置 URI](https://learn.microsoft.com/zh-cn/windows/apps/develop/launch/launch-settings)。

## 界面决策

- 默认 1280×820，按工作区和 DPI 缩小。页面只允许内容区纵向滚动，侧栏固定。
- 首页只放直接功能入口。设备名称、系统版本、硬件详情和日志移到设置；截图留在组件中；删除最近结果。
- 删除营销文案、英文装饰标题、重复摘要。许可证和已安装组件用紧凑行显示。
- 组件中心默认三列，标题单行、说明单行、只保留必要操作。来源和许可证统一放设置。
- 高性能与平衡合并成一个电源计划选择器，读取实际计划，保留自定义状态。
- 老板键先显示覆盖层，再关闭装饰边框、进入全屏并置顶。退出恢复窗口，失败自动回退。模拟屏幕不显示退出提示、阶段说明或演示文案。
- 更新界面参考 [Microsoft Q&A 中的 Windows 11 实际升级屏幕](https://learn.microsoft.com/en-us/answers/questions/2337881/upgrade-from-windows-10-to-windows-11-using-iso-fi)。

## 功能决策

| 功能 | 实现 |
| --- | --- |
| 深度清理 | 固定临时/图形缓存/缩略图白名单，7 天保护，分类扫描令牌和执行前校验 |
| 电脑体检 | 真实内存、磁盘空间、待重启和 Defender 状态；按问题进入对应管理功能 |
| 大文件 | 用户选择个人目录，100 MB 阈值，大小排序，手动选中后强制移入回收站 |
| 重复文件 | 大小分组后逐文件 SHA-256，取消与时间/数量上限，至少保留一份，执行前再次校验 |
| 进程管理 | 当前会话列表、内存和路径，PID+启动时间校验，保护系统进程与自身 |
| 开机管理 | 当前用户 Run 项停用/恢复，不覆盖同名项；保留原始注册表类型；其他项交由 Windows |
| 深度卸载 | 接入已有 BCUninstaller 组件，卸载和残留扫描由成熟组件完成 |
| 弹窗管理 | 枚举当前会话可见顶层窗口，单个正常关闭、按应用路径+完整标题自动关闭、取消规则、通知设置 |
| 网络检测 | DNS、HTTPS 连通性、网卡、IP 和代理状态；只读，保留现有网络配置 |
| 默认浏览器/应用 | 官方 ms-settings:defaultapps；在系统页面选择浏览器或重置关联 |
| 任务栏修复 | 确认后重启当前会话 Explorer，避免擅自重写 Windows 任务栏注册表 |
| 文件显示设置 | 首次备份真实 HKCU 值，读回验证，可恢复缺失值及原值 |

不使用虚构健康评分、定时器安装百分比或“内存加速”。组件检测避免重复启动 winget；设备状态仅在设置页读取。

## 风险与后续范围

默认清理保留 Cookie、登录状态、用户文档、下载文件与回收站。扩展浏览器或软件缓存前，逐项定义路径、最近活动保护和测试样本。重复文件检查使用文件内容，不仅依据文件名和大小。

弹窗自动关闭仅在工具箱运行时生效，动态标题和应用拒绝关闭的窗口可能无法拦截，不声称全系统广告过滤。未添加开机常驻服务或注入其他进程。

正式应用更新仍需单独实现有签名校验的更新链路；WebView2 自动更新不等于工具箱应用更新。此版本不关闭 Defender、Windows 更新、系统还原等系统功能。

- TypeScript/Vite 生产构建和 npm audit 通过。
- 19 项 Rust 测试通过，覆盖临时文件分类、近期保护、过期/复用令牌、变化文件、路径越界、junction、首次备份、缺失值恢复、损坏备份、隔离 HKCU 设置恢复、启动项恢复、重复组保留、同大小不同内容、原生回收站恢复及弹窗匹配。

- 真实文件接口使用工作区隔离样本验证 100 MB 文件、内容相同副本及拒绝整组删除；没有清理用户个人文件。
- 首页在 1280×780、1024×640、896×560、760×520 无横向和纵向溢出。
- 真实老板键 client viewport 等于屏幕 2560×1440（物理 3840×2160），退出恢复正常窗口，不含可见退出提示。
- 有改动的系统设置在隔离 HKCU 测试键验证，未为了测试切换本机电源、重启 Explorer 或卸载已安装软件。
- 第三方来源与 winget 包 ID 已核对；全量第三方安装/卸载、不同 Windows 版本与多显示器仍需要发布前抽查。

- 原生隔离窗口验证：添加精确弹窗规则后自动关闭测试窗口，关闭请求计数增加，随后删除测试规则；未关闭用户应用窗口。
