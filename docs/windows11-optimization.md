# Windows 11 优化调研与产品补齐

日期：2026-10-11。目标是让 WinEase 成为完成任务的工具，而不只是设置入口集合。

## 为什么仍有半成品感

现有清理、空间、应用、体检和网络能力已经具备基础，但大盘扫描可能提前达到预算；部分建议需要到系统页面处理，尚无统一的处理后复检；不同任务的跨页状态此前不完全一致。功能数量不能替代覆盖率、准确的结果和可恢复的执行。

## 本轮已经实现

- 系统工具归为性能与存储、通知与隐私、修复与管理，16 个入口附简短用途与图标。浏览器/默认应用合并。磁盘优化打开 Windows 自带工具，不把 SSD 当机械硬盘强制整理。
- 增加透明效果与移动设备自动播放两项当前用户偏好，首次修改保留原值，恢复时原本不存在的值仍删除，而不是猜一个默认值。缺失/未知状态显示系统默认；错误禁用该项，避免假装已关闭。保留隐藏文件开关，文件扩展名功能仍不提供。
- Windows 设置读取与电源读取分别处理；一项失败不隐藏其他成功数据。单项损坏备份也只限制该项。
- 系统修复使用独立任务状态，跨页保留进度与结果，其他设置不再被这项长任务锁住；修复错误与日志就在操作旁显示。
- 首页体检增加物理磁盘健康和运行状态。只读 Windows 存储提供程序：异常建议先备份，缺失/权限失败标未核实；健康状态不代表完整 SMART 或预测寿命。

## 常见需求汇总与处理方式

| 需求 | WinEase 的处理方式 / 完成度 |
| --- | --- |
| 临时文件、浏览器与应用缓存 | 已有扫描/明细/选择/清理。下一步提高规则覆盖率与批次进度。 |
| Windows 更新与传递优化缓存 | 系统清理规则与 Windows 存储管理配合；不直接递归删除正在使用的更新组件。 |
| 大文件、重复文件与占用图 | 已有独立扫描与回收；大盘索引和渐进结果是当前优先补齐项。 |
| 自动定期清理 | 本轮收录存储感知入口；显示系统原有配置，不擅自启用下载目录或云文件回收。 |
| 开机变慢 | 已有启动开关与保守建议；不能仅因为启动项数量多就禁用全部。后续补充分应用启动影响证据。 |
| 内存/CPU 占用高 | 已有进程管理及内存压力体检；后续增加持续资源占用，避免把单次峰值当故障。 |
| SSD/HDD 维护 | 本轮收录官方磁盘优化工具；健康状态进入体检。自动执行前还需检测维护状态与介质支持。 |
| 性能/续航/睡眠 | 已有互斥电源计划；补齐电源与睡眠入口。保持 OEM 自定义计划，不强推高性能。 |
| 动画、透明效果 | 本轮增加透明效果及官方视觉效果入口。外观偏好独立于推荐优化，不默认关闭全部特效。 |
| 游戏模式与后台录制 | 本轮收录系统设置；针对用户场景，不声称每台电脑都会提升 FPS。 |
| 更新占用带宽 | 本轮收录传递优化；不把更新服务永久关闭当加速。 |
| 广告、建议、诊断反馈 | 本轮按用途收录官方入口；偏好由用户决定，不能宣称关闭它们能明显加速。 |
| 通知/免打扰 | 已有弹窗管理，本轮补充官方通知入口；保留重要安全提示。 |
| 默认浏览器/文件关联 | 合并为默认应用入口；遵循 Windows 的用户确认，不强制修改受保护关联。 |
| 任务栏无响应 | 已有重启当前会话资源管理器并验证；与更深入的系统组件修复区分。 |
| 系统损坏/异常崩溃 | 已有组件修复、系统文件检查和近期事件体检；本轮集中可靠性记录入口。 |
| 驱动异常 | 已有异常设备检查，本轮集中设备管理和 Windows 更新入口；自动修驱动还需硬件匹配、来源校验和回滚。 |
| 网络不通/慢/测速 | 已有网络诊断、备份修复及上下行测速；不清除正常代理/TUN 配置来追求全绿。 |
| 系统恢复 | 本轮收录官方恢复页面；重置电脑不是一键优化动作。 |

## 接下来应按这个顺序做

1. **扫描完整度**：增量文件索引、渐进结果与独立取消；分别标明扫描覆盖和已统计体积，默认不提高危险清理范围。
2. **处理闭环**：每项建议显示问题证据、处理动作及恢复方法，执行后只复检相关范围，明确处理成功/未解决/需重启。
3. **真实性能诊断**：持续 CPU/内存/磁盘占用、启动影响和后台应用证据；输出少量适合当前设备的建议。
4. **清理规则可维护**：规则版本、来源、保护范围和隔离样本回归；实际文件进度与实际释放空间。
5. **发布实机验收**：UAC、原生启动、组件安装卸载、签名更新及旧版本升级；模拟 IPC 不能替代这些验证。

不纳入默认推荐：注册表“垃圾”清除、强制关 Defender/防火墙/系统更新、关闭页面文件、清空待机内存、批量禁用服务、无证据更改网络参数。它们不能作为普适的性能提升配方。

## 主要依据

- [微软：改善 Windows 性能](https://support.microsoft.com/en-gb/windows/experience/performance-optimization/tips-to-improve-pc-performance-in-windows?nochrome=true)：存储、启动程序、资源占用、视觉效果和电源。
- [微软：存储感知](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/manage-drive-space-with-storage-sense)：系统盘自动清理与云文件处理边界。
- [微软：磁盘优化](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/defragment-optimize-your-data-drives-in-windows)：交给 Windows 按磁盘类型处理。
- [Microsoft Learn：设置入口](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings)：核对 URI，避免使用已弃用的全局后台应用入口。
- [Microsoft Learn：设置数据](https://learn.microsoft.com/en-us/windows/apps/develop/settings/settings-common)：透明效果、自动播放的注册表位置和取值；文档描述数据访问，实际写入还通过隔离回归验证。
- [Microsoft Learn：物理磁盘](https://learn.microsoft.com/en-us/powershell/module/storage/get-physicaldisk)：Windows 存储提供程序的健康/运行数据；非完整硬盘寿命检测。

## 验证

- Rust 单元回归：74 项通过；新增磁盘状态/未知数据判断与设置映射覆盖。注册表写入/恢复验证只使用独立测试键。
- 本机体检只读验证通过：读取 SSD 健康与运行状态，近期可靠性事件正确给出关注项；事件不能直接断定原因。
- 本机 Windows 设置只读查询通过：三项分别读取当前值，没有更改用户设置或重启资源管理器。
- 浏览器模拟 IPC：新增 7 组系统工具流程通过，既有 9 组首页与 6 组清理/回收流程通过；覆盖单项读取失败、默认状态直接关闭、恢复、后台修复跨页完成及窗口宽度。
- TypeScript/Vite 构建与 diff 检查通过。原生入口/权限修改的完整实机验收仍需单独完成。

复现：启动 `npm run dev`，通过 Playwright CLI `run-code --filename=scripts/test-system-ui.cjs`；本机只读验证通过 `cargo test --manifest-path src-tauri/Cargo.toml --lib health::tests::current_windows_health_is_readable -- --ignored --nocapture` 与 `windows_settings::tests::current_settings_are_readable_without_changes`。

本轮没有执行本机系统优化、清理、网络修复或更改用户偏好。
